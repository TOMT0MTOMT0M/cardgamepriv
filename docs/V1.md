## Où ça tourne

| Quoi | Où |
|---|---|
| Site | https://cardgamepriv.pages.dev — Cloudflare Pages, projet `cardgamepriv`, branche de production **`master`** |
| Base des joueurs | Convex, équipe `gamersardechois`, projet `cardgamepriv`, déploiement **`dev:wry-chicken-825`** (`https://wry-chicken-825.eu-west-1.convex.cloud`) — celui de `.env.local` |
| Images | bucket R2 `cardgamepriv-art` (servi par `functions/art/[[path]].js`) |
| Code | branche git **`master`**, tag **`v1.0`** (dépôt privé `TOMT0MTOMT0M/cardgamepriv`) |

Le seul lanceur qui touche la prod : `lanceurs\mettre-en-ligne-prod.cmd` (envoie le code Convex sur la base des joueurs,
lance les migrations idempotentes, build, images R2, Pages `--branch=master`). Depuis la V1, **ne plus le lancer à la main** :
passer par `lanceurs\publier-patch.cmd` (voir `docs/V2.md`), qui sauvegarde la base avant.

## Sauvegarder

Double-clic `lanceurs\sauvegarder-v1.cmd` → `sauvegardes\v1\` (hors git) :
- `base-AAAA-MM-JJ-HHMM.zip` : export complet de la base (toutes les tables + fichiers de profil) ;
- `code-v1.0.zip` : le code au tag `v1.0` ;
- `env-local-v1.txt` : copie de `.env.local` (adresses Convex, jeton R2).

Chaque `publier-patch.cmd` fait aussi un export de la base dans `sauvegardes\avant-patch-vX.Y-….zip`.

## Restaurer la V1 si une V2 tourne mal

### 1. Le site seul (le plus courant : bug d'interface, la base est saine)

```
git checkout master
git reset --hard v1.0          (ou le tag du dernier patch sain : vX.Y)
lanceurs\mettre-en-ligne-prod.cmd
```
Cloudflare Pages permet aussi un retour instantané sans build : tableau de bord → Workers & Pages → `cardgamepriv` →
Deployments → le déploiement précédent → **Rollback to this deployment**. Attention : le code Convex, lui, reste celui
du patch ; si le patch a changé des fonctions, refaire l'étape « site + fonctions » ci-dessous.

### 2. Site + fonctions Convex (le patch a changé le serveur, mais pas les données)

```
git checkout master && git reset --hard v1.0
npx convex dev --once          (renvoie les fonctions de la V1 sur la base des joueurs)
lanceurs\mettre-en-ligne-prod.cmd
```
Les schémas sont toujours compatibles vers l'avant (champs optionnels) : la V1 relit sans problème des données
écrites par une V2.

### 3. Les données aussi (un patch a abîmé la base)

**Ça écrase tout ce que les joueurs ont fait depuis l'export** — à ne faire qu'en dernier recours, et prévenir sur Discord.
```
npx convex import --replace-all --path sauvegardes\avant-patch-vX.Y-….zip      (ou sauvegardes\v1\base-….zip)
```
`--replace-all` remplace toutes les tables par celles de l'archive ; `--replace` ne remplace que les tables présentes
dans l'archive. Puis étape 2 pour remettre le code qui correspond.

### 4. Les variables d'environnement Convex

Elles ne sont pas dans l'export. Les valeurs vivent dans le tableau de bord Convex (Settings → Environment Variables) :
`DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_GUILD_ID`, `ALLOWED_DISCORD_IDS`, `DISCORD_WEBHOOK_URL`,
`DISCORD_BOT_TOKEN` (fichier local `.discord-bot-token`), `FRONTEND_URL`, `PUBLIC_SITE_URL`, `CLUB_CODE`, `MAX_PLAYERS`,
`FEEDBACK_READ_KEY` (fichier local `.feedback-key`). Avant de toucher à quoi que ce soit : `npx convex env list --include-values > sauvegardes\env-convex.txt`.

## Repartir d'un PC vierge

1. `git clone https://github.com/TOMT0MTOMT0M/cardgamepriv.git` puis `npm install` ;
2. recréer `.env.local` depuis `sauvegardes\v1\env-local-v1.txt` ;
3. `npx convex login`, `npx wrangler login` ;
4. remettre `.feedback-key` et `.discord-bot-token` (jamais dans git).
